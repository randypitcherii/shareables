Can Snowflake read Unity Catalog Iceberg tables at production scale?

Long image

A

Answer

Yes, with a staged rollout. The design holds up. Before you scale out, check three things: the metadata call rate, the Private Link sign-in path, and a gap in monitoring.

  1. At 30-second refresh, Snowflake's loadTable rate exceeds the measured per-workspace limit once the estate passes about 9,000 tables.1
  2. On Azure, Snowflake can't use Entra sign-in for catalog integrations over Private Link.2
  3. Per-workspace 429s never reach system.access.audit, so audit dashboards miss them.1
  4. UniForm and Iceberg v3 are GA. The open issues are tuning and monitoring, not missing features.3

Applies toMeasured on 2 fresh sandbox workspaces sharing 1 metastore, Nov 2026. Limits are server configuration and can change; treat them as a snapshot, not an SLA.

1

How many loadTable calls will Snowflake make?

Each refresh tick calls loadTable once per active table, so calls per second ≈ active tables ÷ refresh interval in seconds. Example: 10,000 tables ÷ 30 s = 333/s, which is over the 300/s clean ceiling.

Snowflake JIT refresh: size for peak, not average

Snowflake's Just-in-Time refresh (private preview) refreshes metadata at query time, on top of polling.4 With the default 300 s cache window and 30 s polling, reads rarely add calls, so the formula above still holds on average. Commits and refreshes bunch up, so compare your peak rate, not the average, with the ceiling. A cache window shorter than the poll interval adds about one call per table per query. Writes always refresh. A failed refresh can block the query.4

  1. Iceberg REST edge ↗

    Rejects traffic over the per-workspace limit and sends Retry-After: 1. These rejections are not audited.

  2. Shared UC budget ↗

    Rejects traffic over the shared limit with a ServiceUnavailableException. Latency rises first.

  3. Audit log ↗

    Records only the shared-limit 429s, about 10 to 15 minutes late.

How should the rollout go?

Diagram structure
  • Size and wire up prep
  • Pilot tables pilot
  • Clean for a week? ok
  • Few thousand tables grow
  • Full estate full
  • grow → full
  • ok → grow · yes
  • ok → prep · no
  • pilot → ok
  • prep → pilot
  1. Size and wire up ↗

    Set the refresh interval from table count, confirm the Private Link sign-in path, and start the audit and Snowflake refresh monitors.

  2. Pilot tables ↗

    Start with representative tables from several schemas, including the largest.

  3. Clean for a week? ↗

    Look for 429s in either monitor and for conversion failures. If you see any, go back and resize.

  4. Few thousand tables ↗

    Re-check the peak call rate against about 300/s per workspace and about 400/s for the metastore.
