dbt applies one Unity Catalog model two ways, at batch time

Top: the dbt DAG. Bottom: where each path runs. Same model version; a test proves both agree.

The dbt DAG · make ai-ml-inference
model · SQL ai_ml_inference_input The rows to score: 1,000 synthetic text descriptions. Any table works.
path A · Python model ai_ml_inference_embeddings_python Loads the UC model inside mapInPandas. Always on.
path B · SQL model · opt-in ai_ml_inference_embeddings_serving ai_query() against the serving endpoint. On when DBT_AI_ML_INFERENCE_SERVING_ENDPOINT is set.
test · opt-in assert_ai_ml_inference_paths_agree Every row, both paths: cosine similarity ≥ 0.999. Fails on a missing row, wrong model version, or wrong column.
Where each path runs · the model never moves, only who loads it
path A · per build Serverless job run dbt submits the Python model. Pinned env: mlflow, transformers, torch. Exists only while the build runs.
path A Spark tasks load the model mlflow.pyfunc.load_model("models:/…/2") once per task, then score every batch it holds.
path B · per build SQL warehouse Runs the ai_query() model like any SQL and sends the rows to the endpoint in batches.
path B · you create it once Model Serving endpoint Serves v2 from serving_endpoint.json and scales to zero between builds. Create it with:make ai-ml-inference-endpoint
Unity Catalog · model registry system.ai.bge_small_en_v1_5 · v2 A logged MLflow model, 24M-parameter text embeddings, in every workspace. Swap in any UC model by changing two vars. dbt never trains or registers it.
How to choose

Path A: load the model in a Python model

  • No infrastructure outside dbt; compute bills only during the build
  • A build took about 6 minutes here, mostly installing the pinned env
  • Best for scheduled batch scoring that only dbt needs

Path B: ai_query() against an endpoint

  • The scoring model is pure SQL, so it runs on the warehouse
  • The same endpoint also serves apps and other pipelines
  • After an idle period, the first call waits for a cold start

Either way

  • dbt knows only a model URI or an endpoint name
  • For your own models, point both at an alias such as @champion
  • Demo folder: tagged ai_ml_inference, off in production
